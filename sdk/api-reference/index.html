    REST API Reference¶

    Everything in the dashboard and the Python SDK is built on this REST API. Use it from any language. In Python, the SDK is usually simpler: it handles retries, offline queuing and run grouping for you.

    Machine-readable contract

    This page lists every customer-facing endpoint. A published, machine-readable OpenAPI contract with full request and response schemas is planned. Until then, the SDK's method signatures and the examples on each guide page are the reference for payload fields.

    Base URL and versioning¶

    https://api.whiteboxxai.com/api/v1

    Business Cloud tenants use the API address they were given when the tenant was set up. All endpoints are under /api/v1. Additive changes, such as new fields and new endpoints, happen within v1; clients should ignore response fields they don't recognise.

    Authentication¶

    Send an API key as a bearer token on every request:

    curl https://api.whiteboxxai.com/api/v1/models \
  -H "Authorization: Bearer $WHITEBOX_API_KEY"
    • Keys look like wbx_live_.... They're created by administrators in Settings → API keys, and act with the permissions of the administrator who created them.
    • A signed-in session token (about 30 minutes) is also accepted, and is required for actions that must be made by a person, such as voting on a review request.
    • A missing, wrong, revoked or expired credential returns 401.

    Every response carries an X-Request-ID header. Include it when you contact support.

    Errors¶

    Errors share one envelope:

    {
  "error": "HTTPException",
  "detail": "Model not found",
  "status_code": 404
}
    Status error Meaning
    400 HTTPException The request was understood but can't be carried out as sent
    401 HTTPException Missing or invalid credential
    403 HTTPException Not allowed: wrong role, an action that needs a person's own session, or your plan's Governed AI Systems are all in use
    404 HTTPException Doesn't exist in your organization. Records in other organizations are indistinguishable from records that don't exist.
    409 HTTPException Conflict, such as a duplicate name, or a review request that changed after you opened it
    422 ValidationError The body or parameters didn't match the schema; detail lists each problem
    429 QuotaExceeded The Free plan's monthly Governance Events are used up, or a batch is larger than what remains
    429 RateLimitExceeded Too many requests in the current window; wait for Retry-After
    5xx A server error; safe to retry with back-off

    Rate limits¶

    The default rate limit is 100 requests per 60 seconds per client. Responses include X-RateLimit-Limit, X-RateLimit-Remaining and X-RateLimit-Reset. A 429 RateLimitExceeded response also includes Retry-After, in seconds. Prefer batch endpoints for volume.

    Metering and run grouping¶

    Requests authenticated with an API key that record AI activity (logging predictions, LLM calls, RAG retrievals and safety scans, generating explanations, running evaluations, starting agent workflows) count as Governance Events. Reads, configuration, reports and dashboard use don't. Events are counted only for successful responses.

    Group the records of one AI run with the optional header:

    X-WhiteBox-Run-Id: ticket-4821

    Up to 128 letters, digits, ., _, : or -. Predictions, LLM calls, RAG retrievals and safety scans sharing a run id cost one event per 100 records. A value in any other format is ignored.

    Pagination¶

    List endpoints take skip (offset, default 0) and limit (page size). The maximum limit varies by endpoint and is usually 100 or 1,000. A few newer endpoints use limit and offset. Time-range filters take ISO 8601 timestamps, for example start_time=2026-10-01T00:00:00Z.

    Common requests¶

    curl -X POST https://api.whiteboxxai.com/api/v1/models \
  -H "Authorization: Bearer $WHITEBOX_API_KEY" -H "Content-Type: application/json" \
  -d '{
    "name": "credit_scoring",
    "version": "1.0.0",
    "model_type": "xgboost",
    "model_framework": "xgboost",
    "features": ["income", "utilisation", "tenure_months"],
    "baseline_metrics": {"accuracy": 0.94}
  }'

    model_type is one of xgboost, random_forest, neural_network, linear_model, llm, custom.

    curl -X POST https://api.whiteboxxai.com/api/v1/predictions/log \
  -H "Authorization: Bearer $WHITEBOX_API_KEY" -H "Content-Type: application/json" \
  -d '{
    "model_id": "<model-id>",
    "input_data": {"income": 52000, "utilisation": 0.31, "tenure_months": 18},
    "output_data": {"prediction": 0, "probability": 0.12},
    "latency_ms": 4.2
  }'

    curl -X POST https://api.whiteboxxai.com/api/v1/llm/logs \
  -H "Authorization: Bearer $WHITEBOX_API_KEY" -H "Content-Type: application/json" \
  -H "X-WhiteBox-Run-Id: ticket-4821" \
  -d '{
    "provider": "xai",
    "model_name": "grok-4",
    "prompt": "Summarise this complaint...",
    "completion": "The customer reports...",
    "latency_ms": 712,
    "prompt_tokens": 210,
    "completion_tokens": 64
  }'

    # Ad-hoc check, not stored
curl -X POST "https://api.whiteboxxai.com/api/v1/drift/detect/<model-id>?window_size=1000" \
  -H "Authorization: Bearer $WHITEBOX_API_KEY"

# Stored drift reports for a model
curl https://api.whiteboxxai.com/api/v1/drift/reports/<model-id> \
  -H "Authorization: Bearer $WHITEBOX_API_KEY"

    curl -X POST "https://api.whiteboxxai.com/api/v1/report-types/model_card/generate?format=pdf&model_id=<model-id>" \
  -H "Authorization: Bearer $WHITEBOX_API_KEY"

    See Report types reference.

    LLM gateways¶

    The ingest routes are called by the gateway with a wbx_lgw_ gateway token, not an API key; a token only works for its own gateway type, except that a Portkey token is accepted on the OTLP traces route. The other routes need an organisation administrator; rotating the token also needs a signed-in session, not an API key. {provider} is one of litellm, otlp, portkey, kong or azure_apim. The older /api/v1/integrations/litellm/... paths still work and behave the same as {provider} = litellm. See LiteLLM gateway and LLM gateways.
