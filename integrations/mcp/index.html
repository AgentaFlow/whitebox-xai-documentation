    MCP Server¶

    The WhiteBoxXAI MCP server is the MCP Governance Layer for AI assistants and agents. It gives any Model Context Protocol client (Claude Desktop, Claude Code, Cursor, VS Code, LangChain or Semantic Kernel agents, or your own harness) 197 tools over your WhiteBoxXAI data. With them, an assistant can register models, log predictions and LLM calls, check drift, explain predictions, run bias audits, triage alerts, read ISO/IEC 42001 readiness and the risk register, summarise governance review requests, and manage prompt versions.

    Every tool calls the real WhiteBoxXAI API. None returns mocked or placeholder data. When something can't be computed, the tool says so.

    Writing Python application code? Use the SDK instead. The MCP server is for assistants and agents that use WhiteBoxXAI as a tool.

    Let your coding agent set this up

    The whitebox-mcp-server skill teaches an agent to install and configure the server and pick the right tool. Load it with whitebox-governance-rules.

    Two ways to connect¶

    Local (stdio) Hosted (Streamable HTTP)
    What runs where whiteboxxai-mcp runs on your machine; your client starts it Nothing to install; your client connects to https://api.whiteboxxai.com/mcp/
    Credential An API key in WHITEBOXXAI_MCP_API_KEY An Authorization: Bearer header on every request: an API key or a personal sign-in token
    Governance voting Not available Available with a personal sign-in token
    Best for Coding assistants and agents in your own environment Clients that support remote MCP servers, and interactive voting

    Install (local)¶

    Requires Python 3.11 or later.

    pip install whiteboxxai-mcp

    Create an API key in Settings → API keys (administrators only; see API Keys), then check the server starts:

    export WHITEBOXXAI_MCP_API_KEY="wbx_live_..."
whiteboxxai-mcp

    Your MCP client normally starts the command itself; you don't keep it running in a terminal.

    Configuration¶

    Variable Default Purpose
    WHITEBOXXAI_MCP_API_KEY none (required) Your API key (wbx_live_...)
    WHITEBOXXAI_MCP_API_BASE_URL https://api.whiteboxxai.com Your API address. Business Cloud tenants use the address they were given.
    WHITEBOXXAI_MCP_API_TIMEOUT 30 Request timeout, in seconds
    WHITEBOXXAI_MCP_LOG_LEVEL Log level, for example DEBUG

    whiteboxxai-mcp --verbose (or WHITEBOXXAI_MCP_VERBOSE=1) logs request and response metadata, never credential values.

    The local server authenticates only with an API key. If none is set, it exits with code 2 and whiteboxxai-mcp: no credentials configured.

    Connect a client¶

    Add to the client's MCP config: claude_desktop_config.json for Claude Desktop, ~/.cursor/mcp.json (or .cursor/mcp.json in a project) for Cursor.

    {
  "mcpServers": {
    "whiteboxxai": {
      "command": "whiteboxxai-mcp",
      "env": {
        "WHITEBOXXAI_MCP_API_BASE_URL": "https://api.whiteboxxai.com",
        "WHITEBOXXAI_MCP_API_KEY": "wbx_live_..."
      }
    }
  }
}

    claude mcp add whiteboxxai \
  --env WHITEBOXXAI_MCP_API_KEY=wbx_live_... \
  -- whiteboxxai-mcp

    Or add the same mcpServers block as Claude Desktop to a project's .mcp.json. Don't commit a real key; reference an environment variable such as ${WHITEBOXXAI_MCP_API_KEY} in the file.

    VS Code uses a servers key in .vscode/mcp.json, and can prompt for the key instead of storing it:

    {
  "inputs": [
    {
      "type": "promptString",
      "id": "whitebox-key",
      "description": "WhiteBoxXAI API key",
      "password": true
    }
  ],
  "servers": {
    "whiteboxxai": {
      "type": "stdio",
      "command": "whiteboxxai-mcp",
      "env": {
        "WHITEBOXXAI_MCP_API_KEY": "${input:whitebox-key}"
      }
    }
  }
}

    For clients that support remote MCP servers. With Claude Code:

    claude mcp add --transport http whiteboxxai https://api.whiteboxxai.com/mcp/ \
  --header "Authorization: Bearer wbx_live_..."

    In a JSON config that supports remote servers:

    {
  "mcpServers": {
    "whiteboxxai": {
      "type": "http",
      "url": "https://api.whiteboxxai.com/mcp/",
      "headers": { "Authorization": "Bearer wbx_live_..." }
    }
  }
}

    Any MCP client library can start whiteboxxai-mcp over stdio with the environment above, or connect to the hosted endpoint with an Authorization header. For LangChain, the langchain-mcp-adapters package loads the tools into an agent.

    More copy-paste definitions are on Agent Config Definitions.

    Hosted endpoint authentication¶

    • Every request needs its own Authorization: Bearer <token> header: an API key, or a personal sign-in token. There's no fallback to environment variables, and a request without a valid header is refused with 401 before a session starts.
    • Clients or gateways that can't set Authorization (some registries and proxies reserve it) can send an API key in an X-WhiteBox-API-Key: wbx_live_... header instead. If a request carries both, X-WhiteBox-API-Key is used. The header was added in whiteboxxai-mcp 0.3.2.
    • A personal sign-in token expires after about 30 minutes and isn't refreshed by the server. Reconnect with a fresh token, or use an API key for long-running sessions.
    • Activity sent with an API key is metered as Governance Events in the same way as SDK calls.

    MCP Apps: interactive cards¶

    In clients that support MCP Apps, some results render as interactive cards inside the conversation instead of raw JSON:

    Card Shown for
    Explanation card whitebox_explanations_generate, _get, _get_by_prediction
    Alert triage card whitebox_alerts_get_instance, whitebox_alerts_get_triage_context, whitebox_drift_get_report
    Governance dossier card whitebox_governance_list_review_requests, _get_review_request, _submit_decision
    ISO/IEC 42001 status card whitebox_compliance_iso42001_score, _gaps, _status
    Model version diff card whitebox_models_compare_versions, _version_changelog, _architecture_timeline

    How the cards are built:

    • Each card is a sandboxed ui://whitebox/... resource with a strict content security policy: it can't load anything from the network and holds no credentials. Buttons on a card ask your client to call a tool; they don't call WhiteBoxXAI directly.
    • The card and the text result carry the same data and the same plain-language verdict. Clients without MCP Apps support get the full JSON result.
    • Explanation cards replace common personal data patterns, such as email addresses and phone numbers, with [REDACTED:<TYPE>] before display.

    Governance voting¶

    The governance tools let an assistant prepare a review: list what's waiting, open a request's dossier (board, submitter, decisions, comments, vote tally and its evidence snapshot hash), and summarise it. Casting the vote stays with a person:

    • whitebox_governance_submit_decision is an app-only tool. It's hidden from the model and only offered as a button on the governance dossier card, so an assistant can't vote on its own.
    • A vote needs your own sign-in token on the hosted endpoint. An organization API key is refused, and so is the local stdio server, which only uses API keys.
    • Every vote needs a current authenticator code, and two-factor authentication must be on.
    • The vote carries the evidence snapshot hash of the dossier you saw. If the request changed since, it's refused with 409, and you review the current version first.

    See Reviews & Decisions.

    Example prompts¶

    Ask the assistant It calls
    "What models do we have?" whitebox_models_list
    "Has credit_scoring drifted this month? Keep a record." whitebox_drift_detect, then whitebox_drift_create_report
    "Why was this prediction declined?" whitebox_explanations_get_by_prediction or whitebox_explanations_generate
    "What's firing right now, and why?" whitebox_alerts_list_instances, whitebox_alerts_get_triage_context
    "Where are we on ISO 42001?" whitebox_compliance_iso42001_status
    "What's waiting for my review?" whitebox_governance_list_review_requests
    "How did v3 differ from v2?" whitebox_models_compare_versions
    "Roll back the support-bot prompt to the last verified version." whitebox_prompts_rollback

    Tool reference¶

    Tools are named whitebox_<domain>_<action>, across 18 domains. Required arguments are listed; see each tool's input schema in your client for optional ones.

    Current limitations¶

    • No report generation tools. Generate reports with the SDK or the dashboard. Over MCP, an assistant can create and read drift reports and read the evidence reports draw on.
    • Not every administrative endpoint is a tool. Escalation-policy management and bulk alert actions are left out on purpose. If a tool doesn't exist, the assistant should say so rather than simulate it.
    • Workflow analytics can be slow. whitebox_agent_workflows_cost_breakdown, _bottlenecks and _timeline can take up to about 30 seconds.
    • Hosted sessions with a personal sign-in token expire after about 30 minutes; reconnect with a fresh token, or use an API key where you don't need to vote.

    Troubleshooting¶

    whiteboxxai-mcp: no credentials configured (exit code 2). Set WHITEBOXXAI_MCP_API_KEY in the environment the client starts the server with, not only in your shell.

    401 Unauthorized. The key is mistyped, revoked or expired, or (on the hosted endpoint) the Authorization header is missing or the sign-in token has expired.

    403 on a vote. Votes need your own sign-in token, two-factor authentication and an authenticator code. An API key can't vote.

    404 on an id. The record isn't in your organization. Check the id rather than retrying with other credentials.

    429. Either the rate limit (wait for Retry-After) or, on the Free plan, the month's Governance Events are used up.

    Calls hang, then time out. WHITEBOXXAI_MCP_API_BASE_URL isn't reachable from where the server runs. Check the address and WHITEBOXXAI_MCP_API_TIMEOUT.

    Security notes¶

    • Use one API key per client or agent, so you can revoke one without breaking the others.
    • Credential values are never logged; verbose mode logs request metadata only.
    • The server doesn't write model weights or training data anywhere. It only calls the WhiteBoxXAI API.
    • An API key acts with the permissions of the administrator who created it. See API Keys.
